# 모델 서빙 — 영역 관계

> 단일 KServe → llm-d 분산추론 → MaaS 거버넌스의 **3층이 직교적으로 누적**되는 서빙 스택.
> 컴포넌트: [31-KServe](31-KServe.md) · [32-llm-d-분산추론](32-llm-d-분산추론.md) · [33-MaaS](33-MaaS.md)

---

## 언제 무엇을 쓰나 (경계)

| | 무엇 | 언제 |
|---|---|---|
| **KServe InferenceService** | 단일 모델 서빙 | 예측형 모델(scikit/XGBoost/ONNX), 중소 LLM 단일 Pod. 단일 노드로 충분 |
| **llm-d LLMInferenceService** | 분산/분리 추론 | 대규모 LLM, 고처리량, Prefill/Decode 분리·멀티노드·KV-cache aware 라우팅 필요 |
| **MaaS** | 거버넌스 레이어 | 위 둘 앞단에 멀티테넌트 셀프서비스(토큰 인증·quota·showback) 필요 |

핵심: **데이터 평면 = vLLM(KServe/llm-d)**, **지능형 라우팅 = GIE(InferencePool+EPP)**, **거버넌스 평면 = MaaS(Kuadrant/Authorino)**. 세 층이 쌓인다.

## CRD ERD
```
[KServe 단일]
InferenceService (serving.kserve.io/v1beta1)
  ├─참조→ ServingRuntime / ClusterServingRuntime (v1alpha1)
  └─생성(RawDeployment)→ Deployment + Service + (HPA | KEDA ScaledObject)
     생성(Serverless)→ Knative Service        [deprecated]

[llm-d 분산]
LLMInferenceService (serving.kserve.io/v1alpha1·storage v1alpha2)
  ├─합성(baseRefs M:1)→ LLMInferenceServiceConfig (프리셋)
  └─생성→ Deployment/LeaderWorkerSet(decode) + Deployment(prefill)
          + Service + InferencePool (inference.networking.k8s.io/v1)
          + HTTPRoute (gateway.networking.k8s.io) ──backendRef→ InferencePool
          + EPP Deployment/Service (ext-proc :9002)
          ⟂ Gateway (Istio/kgateway) ──ext_proc→ EPP

[MaaS 거버넌스] (maas.opendatahub.io/v1alpha1)
Tenant ──정책→ MaaSSubscription(tokenRateLimits) + MaaSAuthPolicy
MaaSModelRef ──참조→ LLMInferenceService | ExternalModel
  └─front: Gateway(maas-default-gateway) + Kuadrant + Authorino + EnvoyFilter
```

## 통합 데이터 흐름 (MaaS → llm-d 풀스택)
```
Client (Bearer sk-oai-…/OIDC)
  ▼  MaaS Gateway (Gateway API)
  ├─ Authorino: 토큰/그룹 인증·인가 (MaaSAuthPolicy)
  ├─ Kuadrant: 토큰 rate limit (MaaSSubscription.tokenRateLimits)
  ├─ Prometheus/Thanos: 토큰·요청 메터링(showback)
  ▼  (인가 통과)
  llm-d Gateway (Istio/kgateway, Envoy)
  ├─ HTTPRoute → InferencePool
  ├─ Envoy ext_proc → EPP: filter→scorer(prefix/KV-cache aware)→picker
  ▼  선택된 워크로드 Pod
  ├─ Prefill Deployment (compute-bound) ──KV cache(NIXL/RDMA)──▶ Decode Deployment (memory-bound)
  └─ vLLM (:8000, OpenAI /v1/chat/completions)
```

## 3.4 핵심 변동
- **KServe Serverless 모드 deprecated**(2.25~) → **RawDeployment 기본**. 3.3+ 업그레이드 전 2.25에서 미리 마이그레이션 필요.
- **llm-d 분산추론 GA**(3.4, 0.7.1). OCP 4.20+ 필수.
- **MaaS GA**(3.4).
- **ModelMesh(multi-model) deprecated**, modelmesh-serving 레포 아카이브.

## 출처
- 각 컴포넌트 노트 참조. KServe 0.17.0, llm-d 0.7.1, supported-configs 3.x.
