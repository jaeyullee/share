# 파이프라인 / 실험 — 영역 관계

> 모델 개발의 **실험(Workbench) → 추적(MLflow) → 자동화(Data Science Pipelines)** 흐름. 공통으로 S3 오브젝트 스토리지에 의존.
> 컴포넌트: [41-Data-Science-Pipelines](41-Data-Science-Pipelines.md) · [42-Workbenches](42-Workbenches.md) · [43-MLflow](43-MLflow.md)

---

## 관계 ERD
```
[Data Science Project = OpenShift Namespace]
   ├──► Workbench  (Notebook CR: kubeflow.org/v1, namespaced)
   │       │ StatefulSet→Pod(IDE+proxy)+Service+Route/HTTPRoute+PVC
   │       │ Elyra 확장(JupyterLab만) → 파이프라인 제출
   │       ▼
   ├──► DSP 스택  (DSPA CR: ...opendatahub.io/v1, namespaced)
   │       │ APIServer+PersistenceAgent+ScheduledWF+ArgoController+MLMD
   │       │ run 트리거 → Argo Workflow → 단계 Pod(driver+launcher)
   │
   │   ┌───── 공유 아티팩트/추적 ─────┐
   ▼   ▼                             ▼
 [S3 호환 Object Storage]      [MLflow 트래킹 서버]
 (MinIO/ODF/AWS S3)            (mlflow.opendatahub.io/v1, 공유/클러스터급)
   ▲ DSP/Workbench/MLflow 공통    ▲ Workbench가 주 클라이언트
                                     env 자동주입(opendatahub.io/mlflow-instance)
```

- **Namespace 1:N Workbench, 1:N(보통 1) DSPA.** MLflow는 **공유(클러스터급)** 인스턴스, HTTPRoute URL 재작성으로 테넌트 분리.
- **Workbench → DSP**: Elyra(JupyterLab 한정)로 노트북을 파이프라인화.
- **Workbench → MLflow**: `opendatahub.io/mlflow-instance` 어노테이션으로 `MLFLOW_TRACKING_URI` 자동 주입.
- **DSP → Object Storage**: 단계 간/영속 아티팩트 저장(필수).
- **DSP → MLflow**: 공식 자동연동 미확인(컴포넌트 코드에서 MLflow SDK 직접 로깅은 가능).
- **MLflow ↔ RHOAI Model Registry**: 별개 저장소, 자동 동기화 없음(미확인).

---

## 데이터 흐름 (실험→추적→파이프라인화)
1. **실험**: Workbench(JupyterLab)에서 개발 → MLflow SDK로 param/metric/model 기록(자동 주입 URI). 아티팩트는 DB + 스토어.
2. **추적/비교**: MLflow UI에서 run 비교·모델 등록(MLflow 레지스트리).
3. **파이프라인화**: KFP SDK 또는 Elyra로 파이프라인화 → DSP API Server → IR YAML → Argo Workflow → 단계 Pod → 아티팩트 S3, 계보 MLMD.
4. **(선택) 거버넌스**: 배포 모델은 RHOAI Model Registry 등록 → KServe 배포.

---

## 공통 인프라 의존
- **S3 호환 오브젝트 스토리지**: DSP/MLflow/Workbench 공통 백본. 프로덕션은 외부 S3(ODF/AWS), 내장 MinIO는 비지원.
- **인증/노출**: 세 컴포넌트 모두 **Gateway API HTTPRoute + kube-rbac-proxy** 방향 수렴(MLflow는 이미 HTTPRoute, Workbench는 전환 중).
- **DSC managed**: datasciencepipelines, workbenches, **mlflowoperator**(3.4 신규 승격) 모두 DSC `spec.components`로 관리.

## 핵심 주의
- **두 "레지스트리" 혼동**: MLflow 레지스트리(실험 계보) ≠ RHOAI Model Registry(거버넌스). → [51-Model-Registry](51-Model-Registry.md)
