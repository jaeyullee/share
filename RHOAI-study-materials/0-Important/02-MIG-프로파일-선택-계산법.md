# MIG 프로파일 선택 계산법

> 모델을 어떤 MIG 프로파일(슬라이스 크기)에 올릴지 결정하는 절차.
> **메모리 fit으로 후보를 거르고(1차) → SLA로 컴퓨트/대역폭 크기를 정한다(2차).**

---

## 선택 절차 (공식)

```
1) 메모리 fit으로 후보 프로파일 거르기
   필요VRAM = 가중치 × 1.2 + KV  ≤  프로파일 메모리
   (계산법 → 01-LLM-필요VRAM-계산법)

2) SLA로 컴퓨트/대역폭 크기 결정
   - TTFT 빡셈 + 긴 프롬프트  → 컴퓨트(SM) 큰 프로파일
   - throughput/decode 빡셈    → 메모리(대역폭·KV용량) 큰 프로파일

3) 슬라이스 예산 안에서 조합 (컴퓨트 7 + 메모리 8)
   - 남는 슬라이스는 다른 성격 모델로 채워 낭비 최소화 (mixed 전략)
```

---

## A100 MIG 프로파일 표

A100 = **컴퓨트 7슬라이스 + 메모리 8슬라이스**. (H100/H200/B200도 7+8 동일, 메모리 용량만 다름)

| 프로파일 | 컴퓨트(SM) | 메모리 슬라이스 | 대역폭 | 메모리(40GB) | 단독 최대 개수 |
|---|---|---|---|---|---|
| 1g.5gb | 1/7 | 1 | 1/8 | 5GB | 7 |
| 2g.10gb | 2/7 | 2 | 2/8 | 10GB | 3 |
| 3g.20gb | 3/7 | **4** | 4/8 | 20GB | 2 |
| 4g.20gb | 4/7 | 4 | 4/8 | 20GB | 1 |
| 7g.40gb | 7/7 | 8 | 8/8 | 40GB | 1 |

> 3g·7g는 컴퓨트 대비 메모리 슬라이스가 +1 더 붙는다(3→4, 7→8). 컴퓨트 7 vs 메모리 8 비대칭을 메우기 위함.

---

## 성능 매핑: 단계 → 자원 → 지표

추론은 성격이 다른 두 단계로 나뉘고, 각각 다른 자원에 묶인다.

| 단계 | 성격 | 병목 자원 | 영향 지표 |
|---|---|---|---|
| **Prefill** (프롬프트 일괄 처리, 첫 토큰) | 연산 집약 | **컴퓨트(SM)** | **TTFT** (Time To First Token) |
| **Decode** (토큰 1개씩 생성) | 메모리 집약 | **메모리 대역폭** | **TPOT/ITL** (토큰 간격) |
| **배칭** (동시 요청 묶기) | 용량 의존 | **메모리 용량(KV)** | **throughput** (집계 처리량) |

```
prefill 시간 ≈ (프롬프트길이 × 모델크기) ÷ SM 수     → SM↑면 TTFT↓
decode 시간  ≈ 메모리 트래픽 ÷ 메모리 대역폭          → SM 무관, 대역폭이 레버
throughput   ← 배치 크기 ← KV 용량(메모리)
```

**핵심**: MIG는 컴퓨트·대역폭·KV용량이 프로파일에 **세트로** 묶여 나온다. 큰 프로파일 = 셋 다 동시에 ↑.

## SLA → 프로파일 의사결정표

| 워크로드 / SLA 핵심 | 지배 단계 | 병목 자원 | 프로파일 편향 |
|---|---|---|---|
| **짧은 TTFT + 긴 프롬프트** (RAG, 요약) | prefill | 컴퓨트(SM) | 큰 컴퓨트 (4g, 7g) |
| **긴 생성 + 짧은 프롬프트** (창작, 코드) | decode | 메모리 대역폭 | 메모리 슬라이스↑ |
| **고동시성 / 높은 throughput** | decode 배칭 | KV 용량 + 대역폭 | 큰 메모리 |
| **소형 모델 다수 격리** (낮은 부하) | - | 격리·집적도 | 1g 여러 개 |

## 슬라이스 예산 & 낭비 계산

각 프로파일이 먹는 슬라이스(컴퓨트, 메모리)와 단독 최대 시 남는 양:

| 프로파일 | 컴퓨트/개 | 메모리/개 | 단독 최대 | 컴퓨트 남음 | 메모리 남음 |
|---|---|---|---|---|---|
| 1g.5gb ×7 | 1 | 1 | 7 | 0 | **1 (5GB)** |
| 2g.10gb ×3 | 2 | 2 | 3 | **1** | **2 (10GB)** |
| 3g.20gb ×2 | 3 | 4 | 2 | **1** | 0 |
| 7g.40gb ×1 | 7 | 8 | 1 | 0 | 0 |

### 낭비 0 조합 (mixed)
- **7g.40gb** (통째)
- **4g.20gb + 3g.20gb** → 컴퓨트 4+3=7, 메모리 4+4=8 ✅
- 2g.10gb ×3 + 1g.5gb ×1 → 컴퓨트 7, 메모리 7 (5GB만 낭비)

> 비균등 분할(4g+3g 등)은 정상 설계. 각 인스턴스는 독립 격리되어 크기 달라도 간섭 없음. 단 `mixed` 전략 필요 → 노드가 여러 리소스 타입 광고.

## 워크된 예시

| 케이스 | 모델 | 판단 |
|---|---|---|
| RAG 챗봇, 프롬프트 4K, TTFT<1s | 8B FP16 | prefill 무거움 → 1g 부족, **3g/4g** 필요 |
| 짧은 질의+긴 답변, 동시 50명 | 8B FP16 | decode·배칭 관건 → **메모리 큰** 프로파일 |
| 사내 임베딩 모델 다수 | 소형 | 격리만 필요 → **1g 여러 개** |
