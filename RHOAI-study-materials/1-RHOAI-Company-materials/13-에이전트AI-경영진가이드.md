## 도입 — 에이전트 AI 기회

- gen AI 다음 단계 = **autonomous systems**(적응·지속학습). 물리/소프트웨어/혼합. perceive·decide·act.
- 프롬프트 응답이 아니라 **멀티스텝 작업 개시**(툴·API 접근, 시간에 따라 개선).
- Gartner: **2029년까지 에이전트 AI가 일반 고객서비스 이슈 80% 자율 해결, 운영비 30% 절감**.
- 혜택: 운영효율(자율 워크플로) / 비용절감 / 의사결정·실행 가속(실시간 데이터) / 경쟁 차별화(ROI).

## Ch.1 — 엔터프라이즈 에이전트 AI 과제

- AI 워크플로(상당수 에이전트 기반)가 **2024년 3% → 2026년 25%**로 확대 (IBM).

### 과제 1: 복잡한 에이전트 워크플로 오케스트레이션
- 에이전트 AI는 단일 솔루션 아님. 툴·API·프로토콜·데이터소스·ML·LLM·에이전트 이해 필요.
- 필요: 시스템 간 관리(상이한 프로토콜·보안·성능) / 에이전트 간 조율(중복·충돌 방지) / 적절한 툴(설계·테스트·반복).
- **통합 프레임워크 없으면** 또 하나의 도구로 전락.

### 과제 2: 신뢰·신뢰가능 행동 유지
- 자동화와 달리 에이전트는 **동적 추론·자율 결정** → 신뢰성·투명성·컴플라이언스 우려.
- 핵심 질문: 실시간 행동 모니터·거버넌스? 정책·규제 정렬 보장? 결정 설명·책임 측정?
- **관찰성·오버사이트·guardrails**가 기술 요건.

### 과제 3: 효율적 스케일링
- 효과적 파일럿도 스케일 시 실패 가능. LLM 에이전트는 큰 컴퓨트 요구(수십~수백 에이전트 동시).
- 필요: 스케일 업/다운·비용통제 / 하이브리드·멀티클라우드 유연성(데이터·앱 근처) / 거버넌스·보안·성능 일관성.

## Ch.2 — 오픈 플랫폼 접근

- Red Hat AI = 신뢰 인프라·운영 가시성·보안 배포·환경 유연성. 3종(RHEL AI / OpenShift AI / Inference Server).

### 에이전트 워크플로 조립 간소화
- **통합 API 경험**(LLM·오픈 에이전트 프레임워크·RAG 표준화) / **전용 AI 경험**(자산·에이전트·앱 프로토타이핑 단일 환경) / **생태계 지원**(LlamaStack·OpenAI 호환 API, open-weight·파인튜닝).

### 적응·거버넌스 배포
- **Context-aware 실행**(MCP로 의미관련 운영데이터 접근, 의도 정렬 경계) / **통합 관찰성·정책 집행**(RBAC, 결정 추적) / **컴플라이언스 상호운용**(규제 환경 보안태세).

### 스케일·비용효율 플랫폼
- 환경 유연성(데이터센터·클라우드·클러스터·엣지) / 최적 컴퓨트 오케스트레이션(Inference Server로 비용절감, 온프렘·클라우드 재배치) / 보안 스케일링(금융·헬스케어·정부 지원·패치·연속성).

## Ch.3 — 전략 수립

- 풀스케일로 시작하지 말고 **단계적 도입**(고가치·잘 격리된 유스케이스, 짧은 time-to-insight):
  - 고객지원 티켓 triage·해결 / 자동 IT 교정·DevOps 인시던트 / 컴플라이언스 리포트 생성 / 사내 지식베이스 검색 에이전트.
- **준비도 질문 5**: 반복·규칙기반 결정 지연 지점? 에이전트가 접근할 시스템·API·데이터? 저지연 모델 워크플로 인프라? 자율행동 정책·guardrails? 성공 측정?
- **전략 고려**: Interoperability(오픈·모듈, 락인 회피) / Governance by design(처음부터 정책·모니터·설명가능성, 예 HIPAA) / IT 전략에 AI 임베드 / 스킬 개발.
- **준비도 체크리스트**: 자율 에이전트 수혜 업무 1개 식별? 상호작용 시스템·API 파악? 거버넌스·보안 갖춘 추론 인프라? 이해관계자 buy-in? 성공측정·스케일 계획?

## 결론

- 자동화 = 수동 단계 제거가 아니라 **시스템이 결정·적응·지속개선**하게 하는 것.
- Red Hat AI = 오픈·하이브리드 기반. 워크플로 간소화·자율행동 거버넌스·인프라 최적화.
