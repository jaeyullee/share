# Gemma 4 이해

## 1. Gemma 4란?

**Gemma 4**는 Google DeepMind가 2026년 4월 2일에 공개한 **오픈 소스 AI 모델 가족**이다.

쉽게 말하면:
> Google이 만든 초강력 AI(Gemini 3)의 "축소판"을 누구나 무료로 쓸 수 있게 풀어놓은 것.

### 비유로 이해하기

```
Gemini 3 (비공개)     →  Google이 직접 운영하는 "본사 직영 레스토랑"
Gemma 4 (오픈소스)    →  같은 레시피를 공개해서 "누구나 자기 주방에서 요리"할 수 있게 한 것
```

Google의 최신 기술(Gemini 3)을 기반으로 만들어졌지만, 일반 PC나 스마트폰에서도 돌릴 수 있도록 크기를 줄이고 최적화했다.

### 핵심 수치

| 항목 | 내용 |
|---|---|
| 출시일 | 2026년 4월 2일 |
| 제작사 | Google DeepMind |
| 세대 | Gemma 4세대 (Gemini 3 기반) |
| 라이선스 | **Apache 2.0** (상업적 사용 완전 자유) |
| 모델 수 | 4가지 변형 (2B ~ 31B) |
| 지원 언어 | 140개 이상 |

### 라이선스가 왜 중요한가?

이전 Gemma는 Google 자체 라이선스를 썼지만, Gemma 4부터 **Apache 2.0**으로 전환했다. 이게 뭘 의미하냐면:

- 개인 프로젝트에 자유롭게 사용 가능
- **회사에서 상업적으로 사용해도 무료**
- 월간 사용자 수(MAU) 제한 없음 (Meta의 Llama 4는 7억 명 제한이 있음)
- 정부·기업 자체 배포 완전 허용

## 2. 모델 변형 — "어떤 크기가 있나?"

Gemma 4는 **용도에 따라 4가지 크기**로 나뉜다. 옷에 S/M/L/XL 사이즈가 있는 것처럼.

### 2-1. 엣지(Edge) 모델 — 가벼운 모델

스마트폰, 태블릿, 저사양 PC용.

| 모델 | 실제 작동 크기 | 전체 크기 | 컨텍스트 | 입력 가능한 것 |
|---|---|---|---|---|
| **E2B** | 23억 파라미터 | 51억 | 128K 토큰 | 텍스트, 이미지, **오디오** |
| **E4B** | 45억 파라미터 | 80억 | 128K 토큰 | 텍스트, 이미지, **오디오** |

### 2-2. 서버/워크스테이션 모델 — 강력한 모델

고성능 PC, 서버용.

| 모델 | 실제 작동 크기 | 전체 크기 | 컨텍스트 | 입력 가능한 것 |
|---|---|---|---|---|
| **26B-A4B** (MoE) | 38억 파라미터 | 252억 | 256K 토큰 | 텍스트, 이미지, **비디오** |
| **31B** (Dense) | 307억 파라미터 | 307억 | 256K 토큰 | 텍스트, 이미지, **비디오** |

### 용어 해설

**파라미터(Parameter)란?**
> AI가 학습한 "기억"의 개수. 파라미터가 많을수록 더 많은 지식과 패턴을 기억한다.
> 사람으로 치면 뇌의 시냅스 연결 수와 비슷한 개념.

**컨텍스트(Context)란?**
> AI가 한 번에 읽고 기억할 수 있는 텍스트 양.
> 128K 토큰 ≈ 약 300페이지 분량의 책을 한 번에 읽을 수 있다는 뜻.

**"E"는 무슨 뜻?**
> **Effective(유효)**의 약자. E2B는 실제로는 51억 파라미터를 갖고 있지만, 한 번에 23억만 활성화되어 작동한다. 비유하면 "51억 권의 책이 있는 도서관인데, 질문에 따라 23억 권만 빠르게 꺼내 읽는" 구조. 이 덕분에 **작은 메모리에서도 큰 모델의 성능**을 낸다.

**"A4B"는 무슨 뜻?**
> **Active 4 Billion**. 전체 252억 파라미터 중 매 질문마다 **38억만 활성화**된다는 뜻.

**MoE(Mixture of Experts)란?**
> "전문가 혼합" 아키텍처. 128명의 전문가(소규모 신경망)가 있고, 질문이 들어오면 가장 적합한 8~9명만 골라서 답변한다. 나머지는 쉬고 있으므로 전체 크기는 크지만 실제 계산량은 적다.

**Dense(밀집)란?**
> MoE와 반대. 모든 파라미터가 매번 전부 작동한다. 느리지만 품질이 가장 높다.

## 3. 아키텍처 — "어떻게 만들어졌나?"

기술에 관심 없으면 이 섹션은 건너뛰어도 된다. 하지만 "왜 빠르고 똑똑한지"가 궁금하다면 읽어보자.

### 3-1. 기본 구조

Gemma 4는 **Decoder-only Transformer** 아키텍처를 사용한다.

```
입력 텍스트 → [토큰화] → [여러 층의 변환 블록] → 다음 단어 예측 → 출력
```

이건 GPT, Llama, Qwen 등 대부분의 현대 LLM이 쓰는 구조와 같다.

### 3-2. 핵심 혁신 기술

#### (1) 교차 어텐션 (Alternating Attention)

일반 AI는 모든 텍스트를 항상 전체적으로 살펴본다(느림). Gemma 4는:

```
홀수 층: 근처 512~1024 토큰만 집중 (슬라이딩 윈도우) → 빠름
짝수 층: 전체 텍스트를 살펴봄 (글로벌 어텐션)    → 정확함
```

비유: 책을 읽을 때 **한 문단씩 빠르게 훑고** → **중요한 부분은 처음부터 다시 꼼꼼히 읽는** 것과 같다.

#### (2) Per-Layer Embeddings (PLE) — E2B/E4B 전용

E 모델이 작은 크기로도 큰 모델 수준의 성능을 내는 비밀 기술.

```
일반 모델:   토큰 → [임베딩] → 변환 블록 1 → 블록 2 → ... → 출력
E 모델:     토큰 → [임베딩] → 변환 블록 1 → 블록 2 → ... → 출력
                      ↓            ↓           ↓
                   [PLE 보조 신호가 매 층마다 추가 정보 주입]
```

각 변환 블록에 **보조 임베딩 신호**를 계속 넣어줘서, 적은 파라미터로도 풍부한 표현력을 유지한다.

#### (3) 공유 KV 캐시 (Shared KV Cache)

뒷쪽 레이어가 앞쪽 레이어의 계산 결과를 재활용한다. 메모리 절약에 큰 기여.

#### (4) 비전/오디오 인코더

- **이미지**: 원본 비율 유지, 이미지당 70~1120 토큰으로 유연하게 처리
- **오디오** (E2B/E4B): USM 기반 컨포머 아키텍처로 음성 인식

### 4-3. 이전 세대 대비 개선

```
Gemma 3 → Gemma 4 주요 변화:
├── 속도: 최대 4배 빨라짐
├── 배터리: 모바일에서 60% 절약
├── 코딩: Codeforces 110 → 2150 (20배 향상)
├── 멀티모달: 오디오 입력 추가 (E모델)
├── 라이선스: 자체 라이선스 → Apache 2.0 (완전 자유)
└── 컨텍스트: 유지 (128K/256K)
```

## 5. 로컬에서 실행하는 방법

### 5-1. 지원 프레임워크

| 프레임워크 | 난이도 | 특징 |
|---|---|---|
| **Ollama** | 초보자용 | 한 줄 명령으로 실행. 가장 쉬움 |
| **LM Studio** | 초보자용 | GUI 기반. 클릭만으로 설치·실행 |
| **llama.cpp** | 중급 | C++ 기반, 가장 가벼움, 커스터마이징 자유 |
| **vLLM** | 중~상급 | 서버 배포용, 여러 요청 동시 처리에 최적 |
| **HuggingFace Transformers** | 중~상급 | Python 생태계, 파인튜닝에 적합 |
| **MLX** | Mac 전용 | Apple Silicon에 최적화 |

### 5-2. 가장 쉬운 실행법 (Ollama)

```bash
# 1. Ollama 설치 (Linux)
curl -fsSL https://ollama.com/install.sh | sh

# 2. 모델 실행 (원하는 크기 선택)
ollama run gemma4:e2b        # 가장 가벼움 (스마트폰급)
ollama run gemma4:e4b        # 가벼움 (보급형 PC)
ollama run gemma4:26b        # 균형 (게이밍 PC)
ollama run gemma4:31b        # 최고 품질 (고사양 PC)
```

### 5-3. 양자화(Quantization)란?

AI 모델의 **정밀도를 낮춰서 크기를 줄이는 기술**이다.

```
비유: 사진을 JPG로 압축하는 것과 비슷
├── FP16 (원본): 화질 최고, 파일 크기 최대
├── Q8   (고화질): 거의 원본 수준, 크기 절반
├── Q5   (중화질): 약간의 품질 저하, 크기 1/3
├── Q4   (표준):  실용적 품질, 크기 1/4 ← 가장 많이 사용
└── Q2   (저화질): 눈에 띄는 품질 저하, 크기 1/8
```

일반적으로 **Q4_K_M**이 품질과 크기의 최적 균형점이며, 대부분의 사용자에게 권장된다.

| 양자화 포맷 | 도구 | 용도 |
|---|---|---|
| **GGUF** (Q2~Q8) | Ollama, llama.cpp, LM Studio | 로컬 PC 실행 (가장 인기) |
| **GPTQ** | vLLM, AutoGPTQ | GPU 최적화 int4 |
| **AWQ** | vLLM, AutoAWQ | 활성화 인식 양자화 |

## 6. NVIDIA GPU별 실행 가능 여부

### "내 그래픽 카드로 돌릴 수 있을까?"

이것이 가장 중요한 질문일 것이다. 모델별로 필요한 **VRAM(그래픽 메모리)** 양은 다음과 같다.

### 6-1. 모델별 VRAM 요구량

| 모델 | Q4_K_M | Q5_K_M | Q8_0 | FP16 (원본) |
|---|---|---|---|---|
| **E2B** (51억) | ~5 GB | ~6 GB | ~8 GB | ~15 GB |
| **E4B** (80억) | ~5 GB | ~7 GB | ~10 GB | ~15 GB |
| **26B-A4B** (MoE) | ~18 GB | ~22 GB | ~28 GB | ~52 GB |
| **31B** (Dense) | ~20 GB | ~25 GB | ~34 GB | ~80 GB |

> 주의: 26B와 31B는 긴 컨텍스트 사용 시 VRAM이 추가로 필요하다.
> 256K 풀 컨텍스트 기준: 26B Q4 → ~23GB, 31B Q4 → ~40GB

### 6-2. GPU 호환성 매트릭스

#### RTX 30 시리즈

| GPU | VRAM | E2B | E4B | 26B-A4B | 31B |
|---|---|---|---|---|---|
| **RTX 3060** | 12 GB | Q8까지 여유 | Q8 가능 | 불가 | 불가 |
| **RTX 3070** | 8 GB | Q8 가능 | Q4~Q5 가능 | 불가 | 불가 |
| **RTX 3080** | 10 GB | Q8까지 여유 | Q8 가능 | 불가 | 불가 |
| **RTX 3090** | 24 GB | 전체 가능 | 전체 가능 | **Q4 가능** (256K 풀 컨텍스트) | Q4 가능 (짧은 컨텍스트만) |

#### RTX 40 시리즈

| GPU | VRAM | E2B | E4B | 26B-A4B | 31B |
|---|---|---|---|---|---|
| **RTX 4060** | 8 GB | Q8 가능 | Q4~Q5 가능 | 불가 | 불가 |
| **RTX 4070** | 12 GB | 전체 가능 | Q8까지 가능 | 불가 | 불가 |
| **RTX 4080** | 16 GB | 전체 가능 | 전체 가능 | Q4 (짧은 컨텍스트) | 불가 |
| **RTX 4090** | 24 GB | 전체 가능 | 전체 가능 | **Q4 가능** (256K), Q5 (~128K) | Q4 가능 (짧은 컨텍스트만) |

#### RTX 50 시리즈

| GPU | VRAM | E2B | E4B | 26B-A4B | 31B |
|---|---|---|---|---|---|
| **RTX 5070** | 12 GB | 전체 가능 | Q8까지 가능 | 불가 | 불가 |
| **RTX 5080** | 16 GB | 전체 가능 | 전체 가능 | Q4 (짧은 컨텍스트) | 불가 |
| **RTX 5090** | 32 GB | 전체 가능 | 전체 가능 | **Q4~Q5 가능** (풀 컨텍스트), Q8 (~32K) | **Q4 가능** (~128K 컨텍스트) |

### 6-3. 실측 성능 참고 (RTX 4090, 26B-A4B Q4)

| 항목 | 수치 |
|---|---|
| 응답 생성 속도 | **162 토큰/초** |
| 입력 처리 속도 | 8,400 토큰/초 |
| VRAM 사용량 | 19.5 GB |
| 최대 컨텍스트 | 262K 토큰 |

> 162 토큰/초는 사람이 읽는 속도보다 훨씬 빠르다. 체감상 거의 즉시 응답.

### 6-4. 추천 조합 (가성비 기준)

```
예산별 추천:

💰 가성비 (8~12GB GPU: RTX 3060, 4060, 4070, 5070)
   → E2B 또는 E4B Q4
   → 일상 대화, 문서 요약, 간단한 코딩에 충분
   → 오디오 입력까지 가능한 것이 장점

💰💰 밸런스 (24GB GPU: RTX 3090, 4090)
   → 26B-A4B Q4 ← ⭐ 최고의 가성비 조합
   → 31B의 97% 품질을 4B급 속도로 실행
   → 256K 풀 컨텍스트 사용 가능

💰💰💰 최고 품질 (32GB GPU: RTX 5090)
   → 31B Q4 (최대 128K 컨텍스트)
   → 또는 26B-A4B Q5~Q8 (더 높은 품질)
   → 오픈 모델 중 최상위 성능
```

## 7. 경쟁 모델 비교

### 7-1. vs Meta Llama 4

| 항목 | Gemma 4 (31B) | Llama 4 Maverick (400B MoE) |
|---|---|---|
| 종합 지식 (MMLU Pro) | 85.2% | 85.5% |
| 수학 (AIME 2026) | **89.2%** | ~42% |
| 코딩 (LiveCodeBench) | **80.0%** | — |
| 컨텍스트 | 256K | **10M** (Scout) |
| 라이선스 | **Apache 2.0** | Meta 커뮤니티 (7억 MAU 제한) |
| 엣지 모델 | **E2B, E4B (오디오 포함)** | 없음 |
| 멀티모달 | 텍스트, 이미지, 오디오, 비디오 | 텍스트, 이미지 |

## 8. 요약 — 3줄 정리

1. **Gemma 4는 Google이 만든 가장 강력한 오픈소스 AI**로, 30B급에서 오픈 모델 1위 성능이며 Apache 2.0 라이선스로 완전 무료 상업 사용이 가능하다.
2. **E2B/E4B는 8GB 이하 GPU에서도 실행 가능**한 초경량 모델로, 텍스트+이미지+오디오를 모두 처리하며 일반 PC에서 충분히 활용할 수 있다.
3. **RTX 3090/4090 사용자라면 26B-A4B Q4가 최고의 선택**으로, 31B의 97% 품질을 4B급 속도로 얻을 수 있다.

## 9. RTX 4070 Super 사용자 가이드

RTX 4070 Super는 **VRAM 12GB**를 탑재하고 있다. 이 GPU에서 각 모델의 실행 가능 여부는 다음과 같다.

### 9-1. 모델별 적합도

| 모델 | 양자화 | VRAM 사용 | 판정 |
|---|---|---|---|
| **E2B** Q4~Q8 | ~5~8 GB | 여유 있게 실행 |
| **E4B** Q4_K_M | ~5 GB | 여유 있게 실행 |
| **E4B** Q5_K_M | ~7 GB | 쾌적하게 실행 |
| **E4B** Q8 | ~10 GB | 실행 가능 (컨텍스트 짧게) |
| **E4B** FP16 | ~15 GB | 불가 (VRAM 초과) |
| 26B-A4B / 31B | 전체 | 불가 (VRAM 부족) |

### 9-2. 최적 추천: E4B Q5_K_M

**E4B Q5_K_M**이 RTX 4070 Super에서 가장 균형 잡힌 선택이다.

- VRAM 약 7GB 사용 → 나머지 5GB가 컨텍스트 버퍼로 활용되어 **긴 대화도 안정적**
- Q4 대비 품질 향상이 체감됨, Q8 대비 컨텍스트 여유가 훨씬 큼
- 텍스트 + 이미지 + **오디오 입력**까지 모두 가능

### 9-3. 실행 방법

```bash
# 기본 실행 (Q4_K_M 기본 적용)
ollama run gemma4:e4b

# Q5 버전을 직접 지정 (추천)
ollama run hf.co/ggml-org/gemma-4-e4b-it-GGUF:Q5_K_M
```

### 9-4. E2B vs E4B — 왜 E4B인가?

12GB GPU에서 E2B도 아주 쾌적하게 돌아간다. 하지만 **같은 GPU에서 E4B를 돌릴 수 있는데 굳이 E2B를 쓸 이유가 없다**. 벤치마크 비교:

| 시험 | E2B | E4B | 차이 |
|---|---|---|---|
| MMLU Pro | 60.0% | 69.4% | +9.4%p |
| AIME 2026 | 37.5% | 42.5% | +5.0%p |
| LiveCodeBench | 44.0% | 52.0% | +8.0%p |
| MMMU Pro | 44.2% | 52.6% | +8.4%p |

E4B가 모든 벤치마크에서 **8~10%p 높은 성능**을 보여준다. 동일한 하드웨어에서 실행 가능하다면 E4B가 합리적인 선택이다.
