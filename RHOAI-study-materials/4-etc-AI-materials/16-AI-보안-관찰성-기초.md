## AI 보안이 왜 새로운 문제인가

기존 웹 서비스 보안은 입력 검증, 인증, 권한 제어로 대부분 해결됐다. AI 에이전트는 다르다.

- **프롬프트 인젝션**: 사용자 입력이나 외부 문서가 LLM의 행동을 바꿀 수 있다
- **탈옥(Jailbreak)**: "fictional purposes로..." 같은 우회 시도
- **에이전트 스킬 변조**: 스킬 파일을 수정해 악성 코드를 실행시킬 수 있다
- **자격 증명 노출**: 스킬 스크립트에 하드코딩된 API 키

전통적인 보안 도구만으로는 부족하다. AI 특화 통제가 추가로 필요하다.

## Agent Skills 보안 위협 지도

Agent Skills는 `SKILL.md` + 스크립트 파일로 구성된다. 이 구조가 만드는 공격 표면:

| 위협 | 설명 | 대응 |
|------|------|------|
| **파일 변조** | 스킬 파일 무단 수정 | 파일 권한 최소화, 접근 로그 |
| **악성 스크립트** | 스킬에 포함된 악성 코드 | SAST, 멀웨어 스캔, 코드 리뷰 |
| **프롬프트 인젝션** | 외부 문서가 LLM 행동 변경 | 가드레일, 입력 검증 |
| **자격 증명 노출** | API 키 하드코딩 | Trufflehog, OAuth 2.0 |
| **공급망 공격** | 자동 업데이트 시 악성 코드 유입 | 스킬 서명 및 검증 |

### 핵심 원칙: 최소 권한

```
에이전트 권한 ≤ 사용자 권한
작업별로 더 축소 가능하면 축소
allowed-tools로 사용 가능한 도구 제한
```

비유하자면, 에이전트는 **임시 직원**이다. 필요한 서랍만 열 수 있어야 하고, 퇴근 후에는 열쇠를 반납해야 한다.

### 실행 격리

```bash
# 컨테이너 샌드박스로 스킬 실행
# seccomp, AppArmor, Firecracker VM 활용
# 인터넷 egress 제한
# 실행 후 자동 정리
```

## Llama Stack 가드레일: Llama Guard + Prompt Guard

### 두 가드레일의 역할

| 가드레일 | 탐지 대상 | 모델 크기 |
|----------|-----------|-----------|
| **Llama Guard** | 유해 콘텐츠 (범죄, 자해, 혐오 등) | 8B |
| **Prompt Guard** | 탈옥·인젝션 시도 | 86M (경량) |

### 구현 방법

```python
# 모델 등록
client.models.register(model_id="meta-llama/Llama-Guard-3-8B")
client.models.register(model_id="meta-llama/Prompt-Guard-86M")

# Shield 등록
client.shields.register(shield_id="content_safety")   # Llama Guard
client.shields.register(shield_id="prompt_guard")      # Prompt Guard

# Agent API에서 자동 적용
agent = client.agents.create(
    input_shields=["content_safety", "prompt_guard"],
    output_shields=["content_safety"],
    ...
)
```

Agent API를 쓰면 입력/출력마다 수동으로 `run_shield()`를 호출하지 않아도 된다. 자동으로 적용된다.

### 가드레일의 부가 효과

거절해야 할 요청을 LLM이 길게 처리하지 않도록 막는다. **GPU 시간과 비용을 절약**하는 효과가 있다.

## AI 관찰 가능성: OpenTelemetry + Jaeger

### 관찰 가능성의 세 축

```
로그 (Logging)     → 무슨 일이 있었나
메트릭 (Metrics)   → 얼마나 자주, 얼마나 빠르게
분산 추적 (Tracing) → 어디서 시간이 걸렸나
```

AI 애플리케이션에서 분산 추적이 특히 중요하다. LLM 호출 하나가 여러 서비스를 거치기 때문이다.

### 문제: Llama Stack만 추적하면 span이 흩어진다

```
요청 A의 span ─┐
요청 B의 span ─┤ → Jaeger에서 뒤섞임
요청 C의 span ─┘
```

동시 요청이 있으면 어떤 span이 어떤 요청에 속하는지 알 수 없다.

### 해결: Python 앱에서 상위 span 생성

```python
from opentelemetry import trace
from opentelemetry.propagate import inject

tracer = trace.get_tracer(__name__)

with tracer.start_as_current_span("user-request") as span:
    # HTTP 헤더에 traceparent 주입
    headers = {}
    inject(headers)
    
    # Llama Stack API 호출 (traceparent 헤더 포함)
    response = client.inference.chat_completion(
        messages=[...],
        extra_headers=headers
    )
```

`traceparent` 헤더로 trace context가 전파되면, Python 앱 span과 Llama Stack 서버 span이 Jaeger에서 **하나의 통합 trace**로 연결된다.

### 설정 요약

```bash
# Llama Stack 서버 환경변수
OTEL_SERVICE_NAME=llama-stack
TELEMETRY_SINKS=otel_trace,otel_metric
otel_trace_endpoint=http://jaeger:4317

# Python 앱 패키지
pip install opentelemetry-sdk opentelemetry-exporter-otlp opentelemetry-instrumentation-httpx
```

## Bunsen: AI로 테스트 결과 분석하기

### 두 가지 활용 방식

**1. 이상 테스트 탐지 (AI/ML 확장)**
- 과거 테스트 결과로 신경망 학습
- 각 테스트 케이스의 예상 결과를 예측
- 실제 결과와 다르면 "예상치 못한 결과"로 표시

**2. flaky 테스트 탐지 (Python 스크립트)**
- 동일 커밋 + 동일 설정에서 결과가 달라지는 테스트 탐지
- 100줄 미만 스크립트로 구현 가능

### flaky 테스트 탐지 로직

```python
# 핵심 자료구조
all_testruns = {}  # (commit, config) → [Testrun, ...]

for (commit, config), testruns in all_testruns.items():
    if len(testruns) < 2:
        continue  # 비교 불가
    
    # 각 실행의 실패 항목 수집
    failures_per_run = [get_failures(run) for run in testruns]
    
    # 일부 실행에만 나타나는 실패 = flaky
    common_failures = set.intersection(*failures_per_run)
    all_failures = set.union(*failures_per_run)
    flaky = all_failures - common_failures
```

실제 SystemTap 데이터 (693개 커밋, 4,158회 실행)에서 실용적인 성능으로 동작했다.

## OCP 엔지니어가 기억할 것

1. **프롬프트 인젝션은 완전한 해결책이 없다**. 가드레일 + 최소 권한 + 샌드박싱으로 피해를 최소화한다.
2. **Llama Guard + Prompt Guard = 실용적인 가드레일 조합**. Agent API에서 shield를 설정하면 자동 적용된다.
3. **AI 관찰 가능성은 앱 측 계측이 필수**. Llama Stack만으로는 span이 흩어진다. `traceparent` 헤더로 연결해야 한다.
4. **Bunsen으로 flaky 테스트를 자동 탐지**. CI/CD 결과 해석의 신뢰도를 높인다.
5. **에이전트 스킬 파일도 코드다**. SAST, 멀웨어 스캔, 서명 검증을 적용해야 한다.
