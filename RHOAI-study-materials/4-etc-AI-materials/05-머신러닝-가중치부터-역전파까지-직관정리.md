# 머신러닝: 가중치부터 역전파까지 직관 정리

> 비전공자 눈높이 입문 | 2026-06-18 | 예상 읽기 시간: 12분

수식을 외우지 않고 "왜 그렇게 되는가"의 직관만으로 따라가는 정리다. 가중치 → 레이어 → 파라미터 → 점수/손실 → 기울기 → 역전파 → 훈련 순서로, 하나가 다음을 자연스럽게 부른다.

---

## 1. 가중치(weight) = 각 입력의 중요도

집값을 예측한다고 하자. 입력이 면적(`x₁`), 역까지 거리(`x₂`)라면 예측은 이렇게 생겼다:

```
예측값 = w₁·x₁ + w₂·x₂ + b
```

- `w₁`, `w₂` = **가중치**. 각 입력이 결과에 얼마나 영향을 주는지의 숫자.
- `b` = **편향(bias)**. 입력이 0일 때의 기본값(선을 위아래로 이동).

`w₁`이 크면 "면적이 집값에 크게 영향", `w₂`가 음수면 "역에서 멀수록 값이 떨어진다". 즉 가중치는 모델이 각 특징에 매기는 **가중점수**다.

> 비유: 여러 친구에게 식당 추천을 받되, 미식가 친구는 ×0.7(많이 반영), 입맛 이상한 친구는 ×0.05(거의 무시). 이 곱하는 숫자가 가중치다.

---

## 2. 점수 → 정답 뽑기 (분류의 핵심)

고양이/개/새를 맞춘다고 하자. **클래스마다 가중치 세트가 따로 있다.** 입력(사진)은 같지만 가중치가 달라서 클래스별 점수가 따로 나온다:

```
고양이 점수 = w₁ᶜ·x₁ + w₂ᶜ·x₂ + ... + bᶜ
개   점수 = w₁ᵈ·x₁ + w₂ᵈ·x₂ + ... + bᵈ
새   점수 = w₁ᵇ·x₁ + w₂ᵇ·x₂ + ... + bᵇ
```

- **분류**: 점수가 가장 높은 클래스를 정답으로 선택. (실제로는 softmax로 점수를 확률처럼 바꿔 비교 — 대소관계는 그대로)
- **회귀**(집값·온도): 후보 중 고르는 게 아니라 계산된 점수 자체가 답.

---

## 3. 레이어(layer) = 점수 계산을 쌓은 것

`w·x+b`를 한 번만 하면 단순한 직선 관계밖에 표현 못 한다. 그래서 계산을 여러 단계로 **쌓는다**. 그게 레이어다.

레이어 하나에는 뉴런이 여러 개 있고, 뉴런마다 자기 가중치로 점수를 낸다. 핵심은:

> **앞 레이어의 출력 점수 = 다음 레이어의 입력 특징.**

```
[원래 입력]      [레이어1]              [레이어2]            [출력]
면적 ─┐
거리 ─┼──→  뉴런들이 점수 계산  ──→  또 점수 계산  ──→  고양이/개/새
층수 ─┘         (새 특징들)          (새 특징)
```

- 레이어가 깊어질수록 단순 조각 패턴 → 복잡한 조합 패턴으로 **추상화**가 올라간다.
- 이미지면: 1층 선/모서리 → 2층 눈/코 → 3층 얼굴 → 출력 "고양이".

### 양파 구조 (중첩, 더하기 아님)

레이어는 결과를 **더하는** 게 아니라, 앞 출력을 뒤 입력에 **끼워넣는다(중첩)**:

```
출력 = f( W₃ · f( W₂ · f( W₁·x + b₁ ) + b₂ ) + b₃ )
```

함수 안에 함수가 들어가는 양파 구조다. "점수의 점수의 점수"를 거듭 통과시키는 것.

### 비선형(활성화 함수)이 꼭 필요한 이유

점수 계산만 계속 쌓으면 수학적으로 한 번의 계산과 같아진다(직선+직선=직선). 그래서 각 레이어에 **비선형 함수**를 통과시킨다:

```
뉴런 출력 = 활성화함수( w·x + b )
```

가장 흔한 **ReLU** = "음수면 0, 양수면 그대로"(`ReLU(-3)=0`, `ReLU(5)=5`). 이 "꺾임"이 있어야 레이어를 쌓을 때마다 표현력이 진짜로 늘어난다.

### 레이어 종류

| 레이어 | 역할 |
|---|---|
| 입력층 | 원본 특징이 들어오는 곳 (계산 안 함) |
| 은닉층 | 중간 점수 계산 층들 (많을수록 "깊다" = deep learning) |
| 출력층 | 마지막 점수 → 분류면 softmax, 회귀면 숫자 |

## 4. 아키텍처 vs 가중치 vs 파라미터

`f₂( W₂·f₁( W₁·x+b₁ ) +b₂ )` 한 줄에 성격이 다른 둘이 섞여 있다.

| 구분 | 정체 |
|---|---|
| **아키텍처** | 수식의 "모양/골격" — 레이어 수, 활성화 종류, `W`의 크기, 연결 순서. 빈칸 양식. |
| **가중치(=파라미터)** | 그 빈칸 `W`, `b`에 실제로 채워진 숫자들. |
| **모델** | 둘을 합친 것. |

> 빈칸 양식 `f( [□]·f( [□]·x + [□] ) + [□] )`(아키텍처)에, 실제 숫자(가중치)를 채운 것이 모델.
> **같은 아키텍처 + 다른 가중치** → 완전히 다른 능력. (학습 전 랜덤=헛소리, 학습 후=똑똑함. 양식은 같고 숫자만 다름)

- **파라미터 개수 = 가중치 개수.** `gemma-3-4b`의 `4b` = 가중치가 약 40억 개라는 뜻. 클수록 똑똑하지만 무겁고 큰 GPU 필요.
- 다운받은 모델 폴더: `config.json`(아키텍처, 작음) + `*.safetensors`(가중치, 수 GB, 본체) + `tokenizer`(입력↔숫자 변환표). 3종 세트.
- "가중치 공개(open weights)"가 쟁점인 이유: 아키텍처는 어차피 논문에 다 있어 안 숨김. **모델의 가치·비밀은 전부 가중치에 있다.** 그래서 정확히 아는 사람은 "모델 공개"가 아니라 "가중치 공개"라고 콕 집어 말한다.

## 5. 훈련(training) = 좋은 가중치를 찾는 것

훈련의 정체는 **손실을 가장 작게 만드는 w, b 값을 찾는 것**이다. 처음엔 랜덤 숫자로 시작해, 아래 한 "스텝"을 수백만 번 반복한다.

```
1 스텝(한 걸음):
  ① forward:  지금 w,b로 점수·손실 계산                (앞으로)
  ② backward: 각 w,b를 어디로 밀면 손실 주는지 계산 (기울기)  (뒤로)
  ③ update:   모든 w,b를 그 방향으로 머리카락만큼 이동   (동시에)
→ 반복
```

- **손실(loss)** = "얼마나 틀렸나"를 잰 하나의 숫자. 클수록 많이 틀림. 목표 = 0에 가깝게.
- 도착한 w,b 값 = 훈련 결과물 = `*.safetensors`에 저장되는 그 가중치.

> 주의: "w 변화로 점수가 어떻게 변하나 계산"은 훈련 전체가 아니라 **1스텝 안의 한 동작(backward)**일 뿐이다. 그 도구를 반복적으로 써서 최종 w,b를 찾아가는 전체 과정이 훈련.

## 6. 기울기(gradient)와 경사하강법

기울기는 거창한 게 아니라 이 질문의 답이다:

> "이 가중치를 **아주 조금** 키우면, 손실이 어느 방향(+/−)으로 변하나?"

- 기울기 **양수(+)** = "키우면 손실 늘어남" → **줄여야** 손실↓
- 기울기 **음수(−)** = "키우면 손실 줄어듦" → **키워야** 손실↓

그래서 항상 **기울기 반대 방향**으로 이동한다. 이게 공식의 마이너스다:

```
새 가중치 = 기존 가중치 − (학습률) × 기울기
```

### 숫자 예 (가중치 1개)

손실이 그릇(U자) 모양 `손실(w) = (w−3)²`이고 지금 `w=1`(손실=4)이라 하자.

```
w를 1→1.01로 살짝 키우면 손실 = (1.01−3)² = 3.9601  (줄었다 → 이 점 기울기는 음수, −4)
규칙대로 반대(키우는) 쪽으로: 새 w = 1 − 0.1×(−4) = 1.4
손실(1.4) = (1.4−3)² = 2.56   (4 → 2.56, 줄었다 ✅)
```

**해보고 판단한 게 아니라**, 기울기 부호를 보고 "키우는 쪽이 내리막"인 줄 **미리 알고** 갔다.

### 왜 "반드시" 줄어드나 + "작은 걸음" 조건

기울기는 "지금 발밑 바닥이 어느 쪽으로 기울었나"를 잰 값이다. 기운 아래로 구슬을 굴리면 반드시 내려간다 — 그게 "기울어짐"의 뜻이다. 단 곡선은 휘어 있어서 기울기는 **딱 지금 그 점**의 기울기다. 그래서:

- **방향**은 보장 (점수 내려감)
- **보폭**은 작아야 보장. 너무 크면 골짜기를 지나쳐 반대편 오르막에 착지(overshoot):

```
w=1에서 오른쪽이 내리막은 확정.
보폭 0.4 → w=1.4, 손실 2.56  (잘 내려감)
보폭 5.0 → w=6.0, 손실 9.0   (정답 3을 지나쳐 오히려 ↑)
```

> 핵심 오해 교정: "점수가 커질 수도 작아질 수도?" → **점수가 어느 방향으로 변하는지를 먼저 계산하는 게 기울기다.** 현재 w값이 확정이니 그 점의 기울어짐(=점수 변화 방향)도 확정 계산된다. 우리는 그걸 보고 내려가는 쪽으로 민다. 작은 걸음인 한 점수는 반드시 내려간다(커지는 건 보폭 과할 때뿐).

## 7. 역전파(backpropagation)

가중치가 수십억 개일 때, 각각의 기울기("이걸 키우면 손실 늘어? 줄어?")를 효율적으로 **한 번에** 구하는 기법이다.

### 핵심 아이디어: 책임을 거꾸로 떠넘기기 (연쇄법칙)

```
사장(손실) ← 부장(출력층) ← 과장(레이어2) ← 사원(레이어1)
```

최종 결과가 망했을 때, 책임(오차)을 출력 → 입력 쪽으로 한 단계씩 넘긴다. 각 단계에서 "받은 책임 × 내가 위에 미친 영향"을 곱해 앞으로 전달. 이 곱하기가 **연쇄법칙(chain rule)**이다.

### 왜 거꾸로인가 = 재활용

```
w₁ 기울기 = (손실→y 민감도) × (y→h 민감도: w₂) × (h→w₁ 민감도: x)
             ↑ 출력층에서 이미 구한 값을 그대로 재활용
```

출력 쪽에서 구한 중간 결과를 앞 레이어가 받아 곱하기만 하면 된다. 그래서 **한 번의 역방향 통과로 모든 가중치 기울기**가 한꺼번에 나온다. (일일이 따로 구하면 영원히 못 끝남 → 역전파가 딥러닝을 가능케 한 결정적 이유.)

### 한 사이클

```
[Forward]  x → h₁ → h₂ → 손실         (앞으로, 점수·손실 계산 + 중간값 저장)
[Backward] 손실 → 출력층 → W₂ → W₁     (뒤로, 모든 W 기울기 한 번에)
[Update]   모든 W를 동시에 한 발 이동
```

### 짚어둘 점

- Forward의 중간값(h₁,h₂)을 저장해둬야 backward 계산 가능 → 학습은 메모리를 많이 먹는다(추론은 아님).
- 기울기가 곱해지며 전파 → 너무 깊으면 0으로 수렴(소실)하거나 폭발. 이를 막으려 ReLU·정규화·ResNet의 건너뛰기 연결 등이 나왔다.
- 공식을 외울 필요 없음 — PyTorch 등이 `loss.backward()` 한 줄로 자동 처리(autograd).

## 8. 가중치가 여러 개일 때 — 자주 막히는 지점

**Q. 안쪽 w를 바꾸면 다음 레이어 입력(h)이 바뀌는데, h가 어디로 갈지 어떻게 알고 w 방향을 정하나?**

→ h의 움직임은 **예측이 아니라 현재 값으로 계산되는 정해진 숫자**다. `h = w₁·x`이고 `x>0`이면 w₁을 키우면 h는 반드시 커진다. 사슬의 각 고리가 전부 아는 숫자라 점수 방향이 못박힌다.

**Q. 각 w 기울기는 "나머지 고정" 가정인데, 동시에 다 움직이면 가정이 깨지지 않나?**

→ 부분적으로 깨진다. 그래서 **걸음을 작게** 한다. 각자 방향 효과는 ε 크기(1차, 큼), 서로 간섭 효과는 ε×ε 크기(2차, 무시 가능). 작은 걸음이면 간섭이 무시돼 전체는 여전히 내리막. 딛고 나서 **다시 전부 계산**(다음 스텝).

> 그림: w 1개일 때 U자 곡선을, w가 N개면 그냥 **U자 곡선 N개**로 본다. 각 w는 자기 곡선에서 자기 내리막 방향을 따로 읽고, 모두 동시에 한 발씩. (다차원에선 이 곡선들이 합쳐져 "사발" 모양 곡면이 되고, 기울기 벡터가 가장 가파른 내리막을 가리킨다 — 구슬이 굴러내려가듯.)

## 전체 흐름 한눈에

```
모델 = 아키텍처(빈칸 양식) + 가중치(빈칸 숫자 w,b)
훈련 = 손실 최소가 되는 w,b를 찾아 채우는 과정
        └ forward(점수·손실) → backward(기울기) → update(한 발) 반복
기울기 = "w를 밀면 손실이 어느 방향으로 가나" (미리 아는 값)
역전파 = 그 기울기를 출력→입력으로 재활용하며 한 번에 구하는 기법
훈련 끝 = 좋은 w,b 확정 → model.safetensors
다운받은 gemma-3-4b = 누군가 이 훈련을 끝내 찾아둔 40억 개 w,b
```

> "학습이 끝난 모델 = 잘 찾아진 가중치 덩어리."
