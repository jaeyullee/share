# RHOAI Hands-On v1.0 실습자료 검토 항목

이 문서는 검증된 실습 절차를 변경하지 않고, 다른 환경에 적용하기 전에 추가 판단이 필요한 항목을 정리한다. 아래 항목은 오류로 확정한 내용이 아니라 버전, 보안 정책, 인프라 차이에 따라 재검토할 경계 조건이다.

## 추가 확인 필요

### RHOAI와 OpenShift 버전 지원 조합

본 자료는 disconnected OpenShift 4.22와 RHOAI 3.4 조합에서 검증했다. 커리큘럼 XLSX에도 공식 지원 범위와 차이가 있을 수 있음을 명시했다. 팀 또는 고객 환경에 적용할 때는 설치 시점의 Red Hat 지원 매트릭스에서 해당 조합을 다시 확인한다.

### Week5 training image의 Python 의존성

[Week5 Step 4](<Week5-Step4 실습.md>)의 training image build에서 내부 PyPI에 준비된 `boto3==1.40.18`이 `botocore==1.40.76`을 설치한다. 기반 image의 `aiobotocore==2.26.0`은 `botocore>=1.41.0,<1.41.6`을 요구하므로 build 로그에 dependency conflict 경고가 남는다.

현재 실습의 동기식 `boto3` S3 경로와 LoRA 학습은 성공했지만, 같은 image에서 `aiobotocore`를 사용하는 기능까지 보장하지 않는다. 내부 PyPI에 상호 호환되는 `boto3`, `botocore`, `aiobotocore` 조합을 준비한 뒤 pin을 다시 검토한다.

## 환경별 재확인

- 문서의 사설 IP, Route 도메인, StorageClass, VMID, PCI 주소, image digest는 검증 환경 값이다. 다른 클러스터에서는 대응 값을 확인한 뒤 사용한다.
- [Week3 Day14](<Week3-Day14 실습.md>)의 Kuadrant mTLS 비활성화와 InferencePool 제한은 OpenShift CIO GatewayClass를 사용한 검증 토폴로지의 결과다. Service Mesh가 별도로 구성된 환경에는 그대로 일반화하지 않는다.
- [Week6 Step0](<Week6-Step0 사전점검 실습.md>)의 GPU PCI passthrough와 2-GPU 계획은 RTX 5060 Ti와 Proxmox 검증 환경을 기준으로 한다. GPU 모델, IOMMU group, P2P 지원, NUMA 토폴로지가 다르면 사전점검 결과도 달라진다.
- Week5 검증 환경에서는 GitOps push 후 Argo CD가 새 PipelineVersion을 게시하기까지 약 4분 30초가 걸렸다. Tekton은 최대 10분 동안 기다리도록 구성했지만, repository polling 또는 webhook 정책이 다른 환경에서는 동기화 지연을 별도로 확인한다.
