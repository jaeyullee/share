# 에이전트 AI 패턴 — 안전·평가·관찰성 (enabler 관점)

> `agentic-ai-llamastack`(#5, 16모듈) 중심 + `llamastack-on-ocp`(#4), `mcp`(#8).
> 프로덕션 에이전트를 "어떻게 책임감 있게 운영하나"에 초점.
> 연결: [[02-Llama-Stack-핵심]], [[03-MCP-핵심]], [[02-AI-에이전트-도구호출-프롬프트패턴]]

---

## 1. 에이전트 vs 챗봇

- **챗봇** = 수동(사람이 묻고 답). **에이전트** = 자율적으로 **도구를 선택·실행**하고 다단계로 목표 달성.
- 구성: LLM(추론) + 도구(행동) + 메모리/세션(상태) + 정책(안전).

---

## 2. 핵심 패턴 4가지

| 패턴 | 내용 |
|---|---|
| **Tool Calling** | LLM이 함수 메타데이터를 보고 "어느 도구·무슨 파라미터"를 결정 |
| **ReAct** | Thought→Action→Observation 루프. 추론 과정 추적 가능 |
| **멀티턴/세션** | `session_id`로 대화 상태 유지(대명사 해석·컨텍스트 보존) |
| **HITL (Human-in-the-loop)** | 위험 동작 전 사람 확인. 실시간 적응 |

---

## 3. 안전성 (Shields) — Defense in Depth

- **3단 필터링**: ① 입력(프롬프트 주입 방어) ② 도구 호출 검증 ③ 출력 필터.
- **Llama Guard 3**(1B 경량 분류 모델) — 추론 오버헤드 작게 안전 판정.
- 위반 분류 **S1~S7**(예: S1 폭력범죄 … S7 프라이버시) → 카테고리별 정책.
- 프레임워크 차이: Llama Stack은 Shields 기본 제공, **LangGraph는 별도 구현 필요**.

---

## 4. 평가 (Evals) — CI/CD 게이트

- 데이터셋 기반 자동 평가. 두 축:
  - **결정론적 스코링**(문자열 매칭) — 빠르고 싸다.
  - **LLM-as-Judge** — 정성 평가, 단 추가 LLM 호출 비용.
- 용도: 프로덕션 배포 전 **회귀 감지**, 모델 업그레이드 영향 검증.
- "지금 어떤 모델이 서빙 중인가" 확인 테스트는 필수 습관.

---

## 5. 관찰성 (Langfuse)

- **Traces**: 요청 전체 생명주기(LLM 호출·도구 선택·입출력)를 사슬로 기록 → 기존 로깅(레이턴시/에러)보다 한 단계 깊은 가시성.
- **Evals**: 자동 품질검사 연동.
- **Feedback**: 사용자 thumbs-up/down을 특정 trace에 매핑 → 지속 개선 루프 + 규정준수 감사 추적.

---

## 6. 아키텍처 설계 원칙 (데모에서 반복되는 것)

- **마이크로서비스 분리**: 에이전트 로직(추론) ↔ 비즈니스 로직(MCP 서버) 경계 명확.
- **MCP를 얇은 어댑터로**: 기존 REST API를 메타데이터로 감싸기 → [[03-MCP-핵심]]
- **상태 비저장 + session_id**: 서비스 재시작에도 세션 복구.
- **제공자 독립**: 모델 바꿔도 `curl` 동일 → [[02-Llama-Stack-핵심]]
- **오픈소스 이식성**: 전체 스택을 다른 OCP 클러스터로 이전 가능.

---

## 7. 빌드/배포 도구 스펙트럼

- **코드**: Llama Stack SDK / LangGraph(FastAPI).
- **시각**: Langflow(드래그앤드롭, MCP 노드, JSON 버전관리, API 내보내기) — 비개발자/PoC 빠른 구성.
- **IDE**: RHOAI Workbench(Jupyter/VS Code/RStudio, Pod 기반).
- **배포**: Helm 차트로 마이크로서비스 일괄, `LlamaStackDistribution` CRD.

---

## 8. enabler 핵심 메시지

- 에이전트 PoC를 "동작했다"로 끝내지 말 것. 프로덕션 = **안전(Shields) + 평가(Evals) + 관찰성(Langfuse)** 3종을 처음부터.
- 고객 시연 시나리오: "고객 이메일로 인보이스 조회 → 웹검색으로 배송상태 확인 → 응답 합성" 같은 멀티스텝(도구체이닝)이 에이전트 가치를 가장 잘 보여줌.
- 비용 인지: LLM-as-Judge·Shields도 추가 추론 호출 → 토큰/지연 비용 계산에 포함.
- 입문 실습: agentic-ai-llamastack(#5) 모듈 1~7(기능)→8~11(엔터프라이즈 에이전트)→12~14(관찰성/시각화).
